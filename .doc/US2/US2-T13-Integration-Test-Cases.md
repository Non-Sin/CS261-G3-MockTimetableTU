# US2-T13 — Integration Test Cases: UI ↔ API (ลบวิชาจากตารางเรียนจำลอง)

Branch: `docs/US2-T13-design-it-ui-api`
Artefact: Test cases specification
อ้างอิง: US2 DTO & API Spec, US2 API Class Diagram, US2 DTO Class Diagram, UAT (US2-T16)

## 1. ขอบเขต

ทดสอบการทำงานร่วมกันระหว่างหน้าตารางเรียน (checkbox, ปุ่มลบ, ไอคอนลบ) กับ API ลบวิชา

| Endpoint | Path | ใช้กับ |
| --- | --- | --- |
| 1 | `DELETE /api/timetable/entries/{entryId}` | ไอคอนลบของวิชาเดียว |
| 2 | `DELETE /api/timetable/entries?entryIds=7,8` | ปุ่มลบวิชาที่ติ๊ก และลบทุกวิชา |

สิ่งที่ตรวจในทุก case: (ก) request ที่ UI ส่งออกไป (method, URL, ไม่มี body), (ข) การตอบสนองของ UI หลังได้ response

นอกขอบเขต: เปลี่ยนกลุ่มเรียน, undo, กล่องยืนยันก่อนลบ (ถ้ามี ทดสอบเป็น UI test แยก)

## 2. Precondition และข้อมูลทดสอบ

- US2-T05 (API) และ US2-T07 (UI) พร้อมใช้งาน, US1 `getTimetable` พร้อม
- ใช้นักศึกษา demo (`app.timetable.demo-student-id`) ภาคเรียน 1/2568
- **ชุดข้อมูล A:** ตาราง 7 วิชา 21 หน่วยกิต มีเวลาชน 1 คู่ (TU109 กับ LAS101) ตาม frame 1:1057 ของ US1 และ seed ภาคเรียน 1/2568
- **ชุดข้อมูล B:** ตารางที่ไม่เคยเพิ่มวิชา (`entries: []`, `updatedAt: null`)
- **ชุดข้อมูล C:** นักศึกษาอีกคนที่มี entry ของตัวเอง (ใช้ทดสอบ 404)
- **ชุดข้อมูล D:** นักศึกษา demo ที่มี entry 2 ภาคเรียน (ใช้ทดสอบ 400 คนละตาราง)
- เก็บ `entryId` จาก response ของ `POST /api/timetable/entries` เพราะ IDENTITY ให้เลขใหม่ทุกครั้ง

## 3. Test cases: ลบสำเร็จ (UI ↔ API)

| ID | UAT | Scenario | ขั้นตอน | ผลที่คาดหวัง |
| --- | --- | --- | --- | --- |
| IT-01 | TC1 | ลบ 1 วิชาด้วยไอคอนลบ | ใช้ชุด A, กดไอคอนลบของ LAS101 | ส่ง `DELETE /api/timetable/entries/8` 1 ครั้ง ไม่มี body, ได้ 200, LAS101 หายจาก grid และรายการ, วิชาอื่นยังอยู่ที่วัน เวลา กลุ่มเดิม, หน่วยกิตรวมตรงกับ `totalCredits` |
| IT-02 | TC1 | ลบ 1 วิชาด้วย checkbox + ปุ่มลบ | ติ๊ก 1 วิชา → กดปุ่มลบ | ส่ง `DELETE /api/timetable/entries?entryIds=7` (endpoint 2) ได้ 200, ผลบนหน้าจอเหมือน IT-01 |
| IT-03 | TC2 | ลบหลายวิชา | ติ๊ก 2 วิชา (TU109, LAS101) → กดปุ่มลบ | ส่ง `DELETE ...?entryIds=7,8` ครั้งเดียว (join ด้วย comma, ไม่ส่ง body), ได้ 200, เหลือเฉพาะวิชาที่ไม่ได้ติ๊ก, `totalCredits` และ grid ตรงกับ response |
| IT-04 | TC3 | ลบทุกวิชา | เลือกลบทุกวิชา (ส่ง `entries.map(e => e.entryId)`) | ส่ง request ครั้งเดียวพร้อม entryId ทุกตัว, ได้ 200, `entries: []`, `totalCredits: 0`, UI แสดง empty state, `updatedAt` ไม่เป็น `null` จึงแสดงข้อความ "บันทึก…เมื่อสักครู่" |
| IT-05 | - | ลบวิชาที่เวลาชน | ชุด A กดลบ LAS101 | แถบเวลาชนหายไป, `conflicts: []`, `conflictWith` ของ TU109 ว่าง, ไม่มีสัญลักษณ์ชนค้างบนการ์ดหรือ grid |
| IT-06 | - | หลังลบสำเร็จ UI ใช้ response แทน state เดิม | ลบวิชาใดก็ได้ แล้วดู network | UI อัปเดตจาก response เลย (ไม่เรียก `GET /api/timetable` ซ้ำ), checkbox ถูกล้างทั้งหมด, สถานะกลับเป็น `idle`, ตัวนับหน่วยกิตและแถบสรุปถูกต้อง |
| IT-07 | - | `updatedAt` ขยับหลังลบ | จดเวลาที่แสดงก่อนลบ → ลบ 1 วิชา | ข้อความบันทึกล่าสุดเปลี่ยนตามเวลาที่ลบ |
| IT-08 | - | ตารางที่ลบจนว่างต่างจากตารางที่ไม่เคยใช้ | เปรียบเทียบผลของ IT-04 กับชุด B | UI ตัดสินว่าว่างจาก `entries.length === 0` ทั้งสองกรณี, ชุด B ไม่แสดงเวลาบันทึก (`updatedAt: null`) ส่วนหลัง IT-04 แสดงเวลาที่ลบ |

## 4. Test cases: สถานะปุ่มลบ (ไม่มีการเรียก API)

| ID | UAT | Scenario | ขั้นตอน | ผลที่คาดหวัง |
| --- | --- | --- | --- | --- |
| IT-09 | TC4 | ตารางว่างกดลบไม่ได้ | ใช้ชุด B หรือหลัง IT-04 | ปุ่มลบ disabled, ไม่มี request ออกไป |
| IT-10 | - | ยังไม่ติ๊กวิชาใด | ชุด A ไม่ติ๊กอะไร | ปุ่มลบ disabled, ไม่มี request |
| IT-11 | - | ติ๊กแล้วยกเลิกติ๊ก | ติ๊กวิชา → เอาติ๊กออกทั้งหมด | ปุ่มลบกลับเป็น disabled |

## 5. Test cases: Error (UI ↔ API)

ใช้การ mock response หรือสร้างสถานการณ์จริง เช่น ลบวิชาเดียวกันจากอีกแท็บไปก่อน

| ID | Scenario | วิธีสร้างสถานการณ์ | ผลที่คาดหวัง |
| --- | --- | --- | --- |
| IT-13 | 404 ข้อมูลบนหน้าจอเก่า | เปิด 2 แท็บ ลบวิชา X ในแท็บ 1 แล้วกลับมาลบวิชา X ในแท็บ 2 | UI แจ้งว่าตารางมีการเปลี่ยนแปลง, เรียก `GET /api/timetable` ใหม่, รายการตรงกับ server, checkbox ถูกล้าง |
| IT-14 | 404 ปน id ที่มีจริงกับไม่มี | ติ๊ก 2 วิชา โดย 1 วิชาถูกลบไปแล้วจากอีกแท็บ | ได้ 404, **ไม่มีวิชาใดถูกลบ** (all-or-nothing), หลัง refetch วิชาที่ยังอยู่แสดงครบ |
| IT-15 | 400 | mock response เป็น 400 | แสดงข้อความ error ทั่วไป, `DeleteStatus = error`, ตารางบนหน้าจอไม่เปลี่ยน, ปุ่มกลับมากดได้ |
| IT-16 | 500 | mock response เป็น 500 | แสดงข้อความ error, รายการยังอยู่, ไม่ค้างที่ `deleting`, ลองกดลบใหม่ได้ |
| IT-17 | Network ล่ม / timeout | ตัดเน็ตหรือ delay เกินเวลา | `ApiError`/network error ถูกจัดการ แสดงข้อความ, state หน้าจอไม่เพี้ยน, ลองใหม่ได้ |
| IT-18 | หลัง error แล้วลองใหม่สำเร็จ | ต่อจาก IT-16 คืนค่า API เป็นปกติ แล้วกดลบอีกครั้ง | ลบสำเร็จ, ข้อความ error หาย, สถานะกลับเป็น `idle` |

## 6. Test cases: สัญญา API (ยิงตรง/Postman)

ตรวจพฤติกรรมของ API ที่ UI ปกติไม่ส่ง แต่ต้องมั่นใจว่า contract ตรงกับ spec

| ID | Request | ผลที่คาดหวัง |
| --- | --- | --- |
| IT-19 | `DELETE /entries/abc` | 400 (ProblemDetail) |
| IT-20 | `DELETE /entries` (ไม่ส่ง `entryIds`) | 400 |
| IT-21 | `DELETE /entries?entryIds=` (ว่าง) | 400 `ต้องระบุ entryIds อย่างน้อย 1 ตัว` |
| IT-22 | `DELETE /entries?entryIds=7,abc` | 400 |
| IT-23 | `DELETE /entries?entryIds=7,7` | 200 เหมือนส่ง `7` (ตัด id ซ้ำ) |
| IT-24 | `DELETE /entries?entryIds=7&entryIds=8` (key ซ้ำ) | 200 เหมือน `7,8` |
| IT-25 | entryId ของนักศึกษาอื่น (ชุด C) | 404 `ไม่พบวิชาในตารางเรียนของคุณ: entryId ...` และ entry นั้นยังอยู่ |
| IT-26 | id จากสองภาคเรียนของคนเดียว (ชุด D) | 400 `entryIds ต้องเป็นวิชาในตารางเดียวกัน...` และไม่มีอะไรถูกลบ |
| IT-27 | id ของคนอื่นปนกับ id คนละภาค | 404 (ตรวจความเป็นเจ้าของก่อน ไม่รั่วว่า id มีอยู่) |
| IT-28 | ลบ id เดิมซ้ำครั้งที่สอง | 404 |
| IT-29 | `DELETE /entries/?entryIds=7` (มี `/` ก่อน `?`) | 404 (Spring Boot 4 ไม่ถือเป็น path เดียวกัน) |
| IT-30 | ลบทุก entry แล้ว `GET /api/timetable` | `entries: []`, `updatedAt` ไม่เป็น `null` (แถว timetable ไม่ถูกลบ) |

## 7. ข้อสังเกตสำหรับทีม

1. **ปุ่ม "ลบทั้งหมด":** spec ไม่มี endpoint แยก ให้ UI ส่ง entryId ทุกตัวที่แสดงอยู่ ถ้ามีวิชาที่อีกแท็บเพิ่งเพิ่มเข้ามา วิชานั้นจะไม่ถูกลบ (ตามที่ spec ยอมรับ) แต่ response คืนตารางจริง ควรเพิ่ม case นี้ถ้าต้องการครอบคลุม
2. **ไอคอนลบบนการ์ดวิชา:** ถ้า UI ไม่มีไอคอนนี้ IT-01 ให้เปลี่ยนเป็นทดสอบ endpoint 1 ผ่าน Postman แทน
3. **ข้อความ error จริง:** IT-13, IT-15–IT-17 ต้องยืนยันข้อความตาม Figma (frame 1:256, 1:1810) ตอน US2-T07
4. ถ้ามีกล่องยืนยันก่อนลบ ให้เพิ่ม case "กดยกเลิก → ไม่มี request" เป็น UI test
