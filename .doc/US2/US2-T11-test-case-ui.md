# Unit Test Cases: US2 - ลบวิชาจากตารางเรียนจำลอง (UI Component)

เอกสารฉบับนี้อธิบายกรณีการทดสอบ (Unit Test Cases) สำหรับส่วนติดต่อผู้ใช้ (UI) ในฟังก์ชันการลบรายวิชาออกจากตารางเรียนจำลอง

---

## รายการ Test Cases

### 1. Test Case 1 : ลบ 1 วิชาจากตารางเรียนจำลอง
* **Description:** ทดสอบการลบรายวิชา $X$ ออกจากตารางเรียนจำลองเมื่อมีวิชาเรียนอยู่ในตาราง
* **Pre-conditions:** นักศึกษามีตารางเรียนจำลอง และมีรายวิชาเรียน $X$ อยู่ในตาราง
* **Test Steps:** ผู้ใช้คลิกปุ่มลบรายวิชา $X$ ออกจากตารางเรียนจำลอง
* **Expected Result:** รายวิชา $X$ ถูกลบออกจากตารางเรียนจำลองสำเร็จ โดยไม่ส่งผลกระทบกับรายวิชาอื่นๆ ที่เหลืออยู่ในตาราง

---

### 2. Test Case 2 : ลบมากกว่า 1 วิชาจากตารางเรียนจำลอง
* **Description:** ทดสอบการลบรายวิชามากกว่า 1 วิชาพร้อมกันออกจากตารางเรียนจำลอง
* **Pre-conditions:** นักศึกษามีตารางเรียนจำลอง และมีรายวิชาเรียน $X$ และ $Y$ อยู่ในตาราง
* **Test Steps:** ผู้ใช้ทำการเลือกและสั่งลบทั้งรายวิชา $X$ และ $Y$ ออกจากตารางเรียนพร้อมกัน
* **Expected Result:** ทั้งรายวิชา $X$ และ $Y$ ถูกลบออกจากตารางเรียนจำลองพร้อมกันอย่างถูกต้อง โดยไม่กระทบกับรายวิชาอื่นที่เหลือ

---

### 3. Test Case 3 : ลบทุกวิชาจากตารางเรียนจำลอง
* **Description:** ทดสอบการลบรายวิชาทั้งหมดออกจากตารางเรียนจำลองเพื่อเริ่มจัดตารางใหม่
* **Pre-conditions:** นักศึกษามีตารางเรียนจำลองที่มีรายวิชาเรียนอยู่ และต้องการลบรายวิชาทั้งหมด
* **Test Steps:** ผู้ใช้ทำคำสั่งลบรายวิชาทั้งหมดออกจากตารางเรียนจำลอง
* **Expected Result:** ตารางเรียนจำลองกลายเป็นตารางว่างเปล่า (Empty State) พร้อมให้ผู้ใช้สามารถเริ่มต้นเพิ่มรายวิชาใหม่ได้ทันที

---

### 4. Test Case 4 : ตารางเรียนจำลองว่างเปล่า ปุ่มลบต้องถูกปิดใช้งาน (Disabled)
* **Description:** ตรวจสอบสถานะของปุ่มลบเมื่อตารางเรียนจำลองไม่มีรายวิชาอยู่เลย
* **Pre-conditions:** ตารางเรียนจำลองอยู่ในสถานะว่างเปล่า (ไม่มีรายวิชาใดๆ อยู่ในตาราง)
* **Test Steps:** ผู้ใช้สังเกตสถานะของปุ่มลบ หรือพยายามกดคลิกที่ปุ่มลบในหน้าจอ
* **Expected Result:** ปุ่มลบจะต้องอยู่ในสถานะถูกปิดการใช้งาน (Disabled State) หรือถูกซ่อนไว้ เพื่อป้องกันไม่ให้นักศึกษาสามารถกดปุ่มลบได้เมื่อไม่มีวิชาในตาราง
