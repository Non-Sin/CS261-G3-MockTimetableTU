# US1-T11 Design Unit Test Cases ส่วน UI

## User story
US1: เพิ่มวิชาเข้าไปในตารางเรียนจำลอง


## Objective
ออกแบบ Unit Test Cases สำหรับ UI ของ US1
เพื่อทดสอบการเลือกรายวิชา การแสดงข้อมูลรายวิชา
ในตารางเรียนจำลอง และการแสดงข้อมความแจ้งเตือน

## Scope 
ครอบคลุม Conditions of Satisfaction (CoS) ดังนี้:
- Test Case 1: การเลือกรายวิชา
- Test Case 3: การแสดงข้อมูลรายวิชา
- Test Case 4: การแสดงรายวิชาที่เวลาไม่ชนกัน
- Test Case 5: แสดงข้อความแจ้งเตือน
- Test Case 6: การแสดงรายวิชาหลายรายการ

## Test Approach
- ออกแบบ Unit Test Cases โดยอ้างอิงจาก User Story, CoS และ UI Prototype จาก Google Stitch
- ใช้ Mock Data เพื่อกำหนดข้อมูลนำเข้าและผลลัพธ์ที่คาดหวัง โดยรายวิชา วัน เวลา และกลุ่มเรียนยึดตาม seed ภาคเรียน 1/2568 (`db/seed/V20261014_2010__seed_courses_2568_1.sql`)
- ทดสอบการแสดงผลและพฤติกรรมการโต้ตอบของ UI เป็นหลัก
- ยังไม่ได้ดำเนินการทดสอบจริง เนื่องจาก Frontend อยู่ระหว่างพัฒนา
- ชื่อ Component และวิธี Mock อาจปรับเปลี่ยนตาม Implementation จริง
- การตรวจสอบวันและช่วงเวลาเรียนใน UT-UI-03 และ UT-UI-04 เสนอให้ใช้ DOM Attributes เช่น data-day, data-start และ data-end โดยต้องยืนยันรูปแบบกับทีม Frontend เมื่อมี Implementation จริง

## Test Cases

### [UT-UI-01] แสดงรายการรายวิชาที่สามารถเลือกได้

**Related CoS:** Test Case 1

**Preconditions:**
- UI ส่วนรายการรายวิชาพร้อมสำหรับการทดสอบ
- มี Mock Data ของรายวิชา
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

**Test Data:**
- รหัสวิชา: CS180
- ชื่อวิชา: Introduction To User Interface And User Experience
- หน่วยกิต: 3
- Section: 820001

**Test Steps:**
1. Render UI รายการรายวิชาด้วย Mock Data
2. ตรวจสอบว่ามีรายวิชา CS180 ปรากฏในรายการ
3. ตรวจสอบข้อมูลที่แสดงบน UI

**Expected Result:**
- UI แสดงรายวิชา CS180
- UI แสดงชื่อวิชา Introduction To User Interface And User Experience
- UI แสดงหน่วยกิต 3
- UI แสดง Section 820001
- UI แสดงปุ่ม "+ เพิ่มวิชา" บนการ์ดวิชา CS180

### [UT-UI-02] ผู้ใช้สามารถเลือกรายวิชาได้

**Related CoS:** Test Case 1

**Preconditions:**
- มีรายวิชา CS180 แสดงอยู่ในรายการ
- รายวิชา CS180 ยังไม่อยู่ในตารางเรียนจำลอง
- Mock การเรียก `POST /api/timetable/entries` ให้ตอบ `201` พร้อม `Timetable` ที่มี CS180
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

**Test Data:**
- รหัสวิชา: CS180
- ชื่อวิชา: Introduction To User Interface And User Experience
- หน่วยกิต: 3
- Section: 820001

**Test Steps:**
1. Render UI รายการรายวิชาด้วย Mock Data ที่มี CS180
2. ตรวจสอบว่าการ์ดวิชา CS180 แสดงปุ่ม "+ เพิ่มวิชา"
3. จำลองการคลิกปุ่ม "+ เพิ่มวิชา" ของรายวิชา CS180
4. ตรวจสอบการเรียก API และป้ายบนการ์ดวิชา CS180

**Expected Result:**
- ก่อนคลิก การ์ดวิชา CS180 แสดงปุ่ม "+ เพิ่มวิชา"
- หลังคลิก UI เรียก `POST /api/timetable/entries` 1 ครั้ง โดย body เป็น `{ "sectionId": <sectionId ของ CS180 Sec 820001> }`
- หลังได้ response การ์ดวิชา CS180 เปลี่ยนป้ายเป็น "เพิ่มแล้ว" ตาม US1-T05 Spec
- การ์ดวิชาอื่นในรายการยังแสดงปุ่ม "+ เพิ่มวิชา" เหมือนเดิม

### [UT-UI-03] การแสดงข้อมูลรายวิชาในตารางเรียนจำลอง

**Related CoS:** Test Case 3

**Preconditions:**
- UI ตารางเรียนจำลองพร้อมสำหรับการทดสอบ
- มี Mock Data ของรายวิชา CS180 ในตารางเรียนจำลอง
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

**Test Data:**
- รหัสวิชา: CS180
- ชื่อวิชา: Introduction To User Interface And User Experience
- หน่วยกิต: 3
- Section: 820001
- วันที่เรียน: วันจันทร์
- เวลา: 13:30 - 16:30

**Test Steps:**
1. Render UI ตารางเรียนจำลองด้วย Mock Data ที่มีรายวิชา CS180
2. ตรวจสอบว่ารายวิชา CS180 ปรากฏในตารางเรียนจำลอง
3. ตรวจสอบข้อมูลรายวิชา CS180 ที่แสดงบน UI
4. ตรวจสอบ Attribute ที่ระบุวันและช่วงเวลาเรียน เช่น data-day, data-start และ data-end

**Expected Result:**
- UI แสดงรายวิชา CS180 ในตารางเรียนจำลอง
- UI แสดงรหัสวิชา CS180 ถูกต้อง
- UI แสดง Section 820001 ถูกต้อง
- UI แสดงเวลาเรียน 13:30 - 16:30 ถูกต้อง
- UI แสดงรายวิชา CS180 ในช่องวันจันทร์ ช่วงเวลา 13:30 - 16:30

### [UT-UI-04] การแสดงรายวิชาหลายวิชาในตารางเรียนจำลอง

**Related CoS:** Test Case 4, 6

**Preconditions:**
- UI ตารางเรียนจำลองพร้อมสำหรับการทดสอบ
- มี Mock Data ของรายวิชาหลายวิชาที่มีเวลาเรียนไม่ทับซ้อนกัน
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

**Test Data:**
- รหัสวิชา: MA211
- วันที่เรียน: วันอังคาร และ วันพฤหัสบดี
- เวลา: 09:30 - 11:00

- รหัสวิชา: CS111
- วันที่เรียน: วันอังคาร และ วันพฤหัสบดี
- เวลา: 11:00 - 12:30

- รหัสวิชา: ST216
- วันที่เรียน: วันอังคาร
- เวลา: 13:30 - 16:30

**Test Steps:**
1. Render UI ตารางเรียนจำลองด้วย Mock Data ที่มีรายวิชา MA211, CS111, ST216 
2. ตรวจสอบว่ารายวิชาทั้ง 3 วิชาปรากฏในตารางเรียนจำลอง
3. ตรวจสอบวันและเวลาเรียนของแต่ละวิชา
4. ตรวจสอบ Attribute ของแต่ละวิชาที่ระบุวันและช่วงเวลาเรียน เช่น data-day, data-start และ data-end

**Expected Result:**
- UI แสดงรายวิชา MA211, CS111 และ ST216 ครบทั้ง 3 วิชา
- MA211 และ CS111 แสดงในวันอังคารและวันพฤหัสบดี ส่วน ST216 แสดงเฉพาะวันอังคาร
- MA211 แสดงในช่วงเวลา 09:30 - 11:00
- CS111 แสดงในช่วงเวลา 11:00 - 12:30
- ST216 แสดงในช่วงเวลา 13:30 - 16:30
- MA211 และ CS111 แสดงเป็นคนละช่วงเวลาที่ต่อเนื่องกันโดยไม่ทับซ้อนกัน
- มีช่วงเวลาว่าง 12:30 - 13:30 ระหว่าง CS111 และ ST216 ในวันอังคาร
- UI ไม่แสดงรายวิชาซ้ำหรือขาดหายจาก Mock Data

### [UT-UI-05] การแสดงข้อความแจ้งเตือนเมื่อเวลาเรียนชนกัน

**Related CoS:** Test Case 5

**Preconditions:**
- UI ส่วนแสดงข้อความแจ้งเตือนพร้อมสำหรับการทดสอบ
- มี Mock Data ของรายวิชา TU109 อยู่ในตารางเรียนจำลอง 
- มี Mock Data ของรายวิชา LAS101 ที่มีเวลาเรียนชนกับรายวิชาในตาราง
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

**Test Data:**
- รหัสวิชา: TU109
- วันเรียน: วันพุธ
- เวลา: 09:30 - 12:30
- สถานะ: conflict
- ชนกับ: LAS101

- รหัสวิชา: LAS101
- วันเรียน: วันพุธ
- เวลา: 09:30 - 12:30
- สถานะ: conflict
- ชนกับ: TU109

**Test Steps:**
1. Render UI ส่วนแสดงข้อความแจ้งเตือน
2. ตรวจสอบว่าข้อความแจ้งเตือนปรากฏบน UI
3. ตรวจสอบหัวข้อและรายละเอียดข้อความแจ้งเตือน
4. ตรวจสอบว่ารหัสวิชาและช่วงเวลาที่ชนกันแสดงถูกต้อง

**Expected Result:**
- UI แสดงหัวข้อ "ตรวจพบเวลาเรียนซ้อนทับกัน"
- UI แสดงข้อความ "เวลาเรียนชนกัน"
- UI แสดงรหัสวิชา TU109 และ LAS101
- UI แสดงวันพุธ เวลา 09:30 - 12:30 น.
- UI แสดงคำแนะนำให้สลับกลุ่มเรียนหรือเลือกรายวิชาอื่น
