# Integration Test Cases: US1 - ระหว่าง UI กับ API (UI & API Integration)

เอกสารฉบับนี้อธิบายกรณีการทดสอบแบบผสมผสาน (Integration Test) ระหว่างฝั่งหน้าบ้าน (UI Components จาก Figma) และฝั่ง API Endpoints สำหรับ User Story 1 (ตาม Task US1-T13) โดยอ้างอิงสถาปัตยกรรมจาก US1-T06 และหน้าจอการใช้งานจริง

---

## ภาพรวมการทดสอบ (Overview)
* **เป้าหมาย:** ตรวจสอบการส่งคำขอ (Request) จากการกระทำของผู้ใช้บนหน้าจอ UI ไปยัง API Endpoints และการอัปเดตการแสดงผล (Rendering / State Update) บนหน้าเว็บอย่างถูกต้อง
* **ขอบเขต:** ครอบคลุมการทำงานร่วมกันของ 3 ส่วนหลักตามหน้าจอระบบ MockTimetableTU:
  1. การค้นหาและกรองรายวิชา (`GET /api/courses`)
  2. การเพิ่มวิชาลงตารางเรียนและการแสดงผล Grid (`POST /api/timetable/entries`)
  3. การโหลดข้อมูลตารางเรียนเมื่อเริ่มต้นใช้งาน (`GET /api/timetable`)

---

## รายการ Integration Test Cases

### 1. IT-UI-API-01 : ค้นหาและกรองรายวิชาแสดงผลบนหน้า UI (`GET /api/courses`)
* **Description:** ทดสอบเมื่อผู้ใช้งานกรอกคำค้นหา (เช่น "CS111" หรือชื่อวิชา) หรือเลือกฟิลเตอร์หมวดหมู่ (วิชาบังคับ, ศึกษาทั่วไป ฯลฯ) บน UI ระบบจะส่ง Request ไปยัง API และนำผลลัพธ์มาแสดงเป็นการ์ดรายวิชาและ Section พร้อมปุ่ม `+ เพิ่มวิชา` อย่างถูกต้อง
* **Pre-conditions:** มีข้อมูลรายวิชาและกลุ่มเรียนอยู่ในระบบ
* **Test Steps:**
  1. ผู้ใช้งานพิมพ์คำค้นหาในช่อง "ค้นหารายวิชา" และเลือกหมวดหมู่บนหน้า UI
  2. UI ส่ง HTTP Request `GET /api/courses?academicYear=2026&semester=1&q=CS111&category=...` ไปยัง Backend
  3. Backend ประมวลผลและส่งข้อมูลรายวิชาพร้อมรายการ Section กลับมาในรูปแบบ JSON
* **Expected Result:** 
  * UI ได้รับ HTTP Status `200 OK`
  * หน้าจอแสดงผลการ์ดรายวิชา รายละเอียด Section (เช่น เวลาเรียน ห้องเรียน อาจารย์ผู้สอน) และปุ่ม `+ เพิ่มวิชา` ตรงกับข้อมูลที่ค้นหา

### 2. IT-UI-API-02 : เพิ่มวิชาลงตารางเรียนและอัปเดต Grid ทันที (`POST /api/timetable/entries`)
* **Description:** ทดสอบเมื่อผู้ใช้งานคลิกปุ่ม `+ เพิ่มวิชา` บนการ์ดรายวิชา ฝั่ง UI จะส่ง `sectionId` ไปยัง API และเมื่อสำเร็จ UI จะอัปเดตช่องตารางเรียน (Timetable Grid เป็นสีส้ม) พร้อมเพิ่มรายชื่อลงในกล่อง "วิชาที่เพิ่มแล้ว"
* **Pre-conditions:** มีรายวิชาและกลุ่มเรียนแสดงอยู่บนผลการค้นหาหน้า UI
* **Test Steps:**
  1. ผู้ใช้งานคลิกปุ่ม `+ เพิ่มวิชา` ของ Section ที่ต้องการ
  2. UI ส่ง HTTP Request `POST /api/timetable/entries` พร้อมส่ง `sectionId` ไปยัง Backend
  3. Backend บันทึกข้อมูลและส่ง Response ข้อมูลตารางเรียนชุดใหม่กลับมา
* **Expected Result:** 
  * API ตอบกลับด้วยสถานะ `201 Created` พร้อมข้อมูลตารางเรียน
  * UI อัปเดตตารางสอน (Grid) โดยแสดงช่องคาบเรียนของวิชานั้น และอัปเดตรายการในส่วน "วิชาที่เพิ่มแล้ว" รวมถึงแสดงจำนวนหน่วยกิตรวมให้อัตโนมัติ

### 3. IT-UI-API-03 : การจัดการ Error เมื่อเกิดข้อผิดพลาด เช่น วิชาซ้ำหรือเกินหน่วยกิต (`409 Conflict`)
* **Description:** ทดสอบเมื่อผู้ใช้งานพยายามกดเพิ่มวิชาที่ซ้ำกันหรือเกินโควตาหน่วยกิต (`maxCredits`) ระบบ Backend จะส่งสถานะ `409 Conflict` และ UI จะต้องดึงข้อความจาก ProblemDetail มาแสดงเตือนผู้ใช้โดยหน้าเว็บไม่พัง
* **Pre-conditions:** มีวิชานั้นอยู่ในตารางเรียนแล้ว หรือลงทะเบียนถึงหน่วยกิตสูงสุดแล้ว
* **Test Steps:**
  1. ผู้ใช้งานคลิกปุ่ม `+ เพิ่มวิชา` สำหรับวิชาที่เงื่อนไขไม่ผ่าน
  2. UI ส่งคำขอไปยัง API และได้รับ HTTP Status `409 Conflict` พร้อมรหัสข้อผิดพลาด (`COURSE_ALREADY_IN_TIMETABLE` หรือ `CREDIT_LIMIT_EXCEEDED`)
* **Expected Result:** 
  * UI สามารถแกะข้อมูล ProblemDetail และแสดงกล่องข้อความแจ้งเตือน (Alert / Pop-up) ให้ผู้ใช้งานทราบสาเหตุที่เพิ่มวิชาไม่ได้ทันที

### 4. IT-UI-API-04 : โหลดข้อมูลตารางเรียนเมื่อเข้าหน้าเว็บ (`GET /api/timetable`)
* **Description:** ทดสอบเมื่อเปิดหน้าเว็บไซต์ตารางเรียนจำลอง ฝั่ง UI จะทำการเรียก API เพื่อดึงข้อมูลตารางเรียนทั้งหมดของนักศึกษามาเรนเดอร์ลงบน Grid ตามวันและเวลา
* **Pre-conditions:** นักศึกษามีข้อมูลตารางเรียนที่บันทึกไว้ในระบบแล้ว
* **Test Steps:**
  1. ผู้ใช้งานเปิดเข้าหน้าเว็บตารางเรียนจำลอง
  2. UI ส่ง HTTP Request `GET /api/timetable?academicYear=2026&semester=1` ไปยัง Backend
  3. Backend ดึงข้อมูลตารางเรียนและรายการวิชาที่เคยลงไว้ส่งกลับมา
* **Expected Result:** 
  * API ตอบกลับด้วยสถานะ `200 OK`
  * UI นำข้อมูลคาบเรียนมาวาดลงบนตาราง (Timetable Grid) และแสดงรายการใน "วิชาที่เพิ่มแล้ว" ให้ตรงกับข้อมูลในระบบทันทีตั้งแต่เปิดหน้าเว็บ
