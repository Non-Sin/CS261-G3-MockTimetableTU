# Integration Test Cases: US1 - ระหว่าง UI กับ API (UI & API Integration)

เอกสารฉบับนี้อธิบายกรณีการทดสอบแบบผสมผสาน (Integration Test) ระหว่างฝั่งหน้าบ้าน (UI Components จาก Figma) และฝั่ง API Endpoints สำหรับ User Story 1 (ตาม Task US1-T13) โดยอ้างอิงสถาปัตยกรรมจาก US1-T06, ข้อกำหนดระบบอัปเดตล่าสุด และชุดข้อมูลทดสอบ (Seed Data) ประจำภาคการศึกษา 1/2568

---

## 1. ขอบเขต

ทดสอบการทำงานร่วมกันระหว่างหน้าค้นหา/ตารางเรียน (ช่องค้นหา Prefix, ปุ่ม `+ เพิ่มวิชา`, Grid ตารางเรียน) กับ API ของ User Story 1

| Endpoint | Path | ใช้กับ |
| --- | --- | --- |
| 1 | `GET /api/courses` | ค้นหาและกรองรายวิชา (Prefix Search) |
| 2 | `POST /api/timetable/entries` | เพิ่มรายวิชาลงตารางเรียนจำลอง |
| 3 | `GET /api/timetable` | โหลดข้อมูลตารางเรียนเมื่อเข้าหน้าเว็บ |

- **สิ่งที่ตรวจในทุก case:** (ก) request ที่ UI ส่งออกไป (method, URL, query parameters, request body), (ข) การตอบสนองและการอัปเดตสถานะของ UI หลังได้รับ response
- **นอกขอบเขต:** การลบวิชา (เป็นของ US2), การจัดการหน้าจอ Login, การตรวจสอบระบบฐานข้อมูลเชิงลึก

---

## 2. Precondition และข้อมูลทดสอบ

- **ปีการศึกษา/ภาคการศึกษา:** กำหนดใช้ `academicYear=2568` และ `semester=1` ตาม Seed Data ปัจจุบันของระบบ
- **ชุดข้อมูล A:** ข้อมูลรายวิชาภาคการศึกษา 1/2568 ที่มีวิชาขึ้นต้นด้วย `CS` (เช่น `CS111`) และวิชาอื่นๆ เช่น `ST216` (ที่มีคำว่า `STATISTICS`) เพื่อทดสอบ Prefix Search
- **ชุดข้อมูล B:** ตารางเรียนที่ไม่เคยเพิ่มวิชา (`entries: []`, `updatedAt: null`) ของนักศึกษาใหม่
- **ชุดข้อมูล C:** สถานการณ์หน่วยกิตเต็มโควตา หรือเวลาเรียนชนกัน (`TIME_CONFLICT`)

## 3. Test cases: ค้นหาและเพิ่มวิชาสำเร็จ (UI ↔ API)

| ID | UAT | Scenario | ขั้นตอน | ผลที่คาดหวัง |
| --- | --- | --- | --- | --- |
| IT-01 | TC1 | ค้นหารายวิชาด้วย Prefix | พิมพ์คำว่า `CS` ในช่องค้นหา | ส่ง `GET /api/courses?academicYear=2568&semester=1&q=CS`, ได้ 200, หน้าจอแสดงวิชาที่ขึ้นต้นด้วย CS (เช่น CS111) แต่ **ไม่แสดง** วิชา ST216 (เนื่องจากมีคำว่า CS อยู่ตรงกลาง) |
| IT-02 | TC2 | ค้นหาไม่พบข้อมูล | พิมพ์คำค้นหาไม่มีจริง เช่น `XYZ999` | ส่ง GET request, ได้ 200 พร้อมลิสต์ว่าง (`[]`), UI แสดงสถานะ Empty State "ไม่พบรายวิชา" |
| IT-03 | TC3 | เพิ่มวิชาด้วยปุ่ม `+ เพิ่มวิชา` | คลิกปุ่ม `+ เพิ่มวิชา` ของวิชาที่ต้องการ | ส่ง `POST /api/timetable/entries` (ส่ง `sectionId`), ได้ 201 Created พร้อม Response Body ตารางเรียนชุดใหม่, **UI อัปเดต Grid และช่อง "วิชาที่เพิ่มแล้ว" ทันทีโดยไม่ต้องเรียก `GET /api/timetable` ซ้ำ** |
| IT-04 | TC7 | โหลดตารางเรียนกรณีมีข้อมูล | เปิดเข้าหน้าเว็บตารางเรียน | ส่ง `GET /api/timetable?academicYear=2568&semester=1`, ได้ 200, UI นำข้อมูลมาเรนเดอร์ลง Grid และรายการวิชาถูกต้อง |
| IT-05 | TC8 | โหลดตารางเรียนกรณีตารางว่าง | นักศึกษาใหม่เปิดเข้าหน้าเว็บ | ส่ง GET request, ได้ 200 (`entries: []`), UI แสดงตารางว่างพร้อมให้เริ่มเพิ่มวิชา |

## 4. Test cases: สถานะปุ่มและข้อจำกัด UI (ไม่มีการเรียก API หรือบล็อกฝั่ง UI)

| ID | UAT | Scenario | ขั้นตอน | ผลที่คาดหวัง |
| --- | --- | --- | --- | --- |
| IT-06 | TC6 | หน่วยกิตเกินขอบเขต (`maxCredits`) | พยายามเพิ่มวิชาที่ทำให้เกินโควตาหน่วยกิต | ฝั่ง UI ตรวจสอบและปิดกั้นการกดเพิ่มวิชา (Disabled) ทันทีโดยไม่มีการยิง Request ซ้ำซ้อน (แต่ฝั่ง API หากยิงตรงจะตอบ 409) |
| IT-07 | - | กันการกดปุ่มเพิ่มซ้ำระหว่างรอ Response | หน่วงเวลาตอบกลับของ API แล้วคลิกรัวๆ ที่ปุ่ม `+ เพิ่มวิชา` | มี Request ออกไปครั้งเดียว, ปุ่มอยู่ในสถานะ Disabled ระหว่างโหลด, กลับเป็นปกติเมื่อเสร็จสิ้น |

## 5. Test cases: Error Handling (UI ↔ API)

| ID | Scenario | วิธีสร้างสถานการณ์ | ผลที่คาดหวัง |
| --- | --- | --- | --- |
| IT-08 | 409 วิชาซ้ำ / วิชาเดิมคนละกลุ่ม | เพิ่มวิชาที่มีอยู่แล้วในตาราง หรือเพิ่มวิชาเดิมแต่เปลี่ยน Section | API ตอบกลับ `409 Conflict` (เช็กซ้ำก่อนหน่วยกิต), UI แกะ ProblemDetail แสดง Pop-up แจ้งเตือนสาเหตุให้ผู้ใช้ทราบ |
| IT-09 | 409 เวลาเรียนชนกัน (`TIME_CONFLICT`) | เพิ่มวิชาที่มีวันและเวลาทับซ้อนกับวิชาในตาราง | API ตอบกลับ `409 Conflict`, UI แสดงกล่องข้อความเตือนเวลาเรียนชนกันชัดเจน |
| IT-10 | 400 Bad Request | จำลองส่ง Request ข้อมูลพารามิเตอร์ไม่ถูกต้อง | API ตอบ 400, UI แสดงข้อความ Error ทั่วไปและหน้าเว็บไม่พัง (Graceful Handling) |
| IT-11 | 500 Internal Server Error | จำลอง Server ขัดข้อง | UI แสดง Toast Message แจ้งข้อผิดพลาด, ผู้ใช้สามารถลองกดทำรายการใหม่ได้ |
| IT-12 | Network Timeout / ล่ม | ตัดการเชื่อมต่ออินเทอร์เน็ตระหว่างกดเพิ่มวิชา | ระบบจัดการ Network Error, แสดงข้อความแจ้งเตือนสถานะเครือข่าย, สถานะหน้าจอไม่ค้าง |
