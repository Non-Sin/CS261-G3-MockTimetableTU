# US6-T19 — ร่างการ์ด Maintenance

ร่างสำหรับส่งต่อเจ้าของงาน US6-T07 (`sitch28-nin`, PR #112) ไม่ใช่การ์ดที่สร้างบนบอร์ดแล้ว และยังไม่ได้แจ้งผ่านบริการภายนอก ถ้ามีการ์ดจาก [T17 PR #120](https://github.com/Non-Sin/CS261-G3-MockTimetableTU/pull/120) อยู่แล้ว ให้เพิ่มหลักฐาน T19 ในเรื่องเดิม ไม่เปิดซ้ำ

Source ที่พบ: `aea7b980e022e4fee4ffa04daea0499f26ff3821`

## 1. [P3] เลือก Sec แรกที่ยังไม่อยู่ในตารางให้ตาม T15

- Label: Maintenance
- เคส: ST-US6-10; เชื่อม T17 IT-22
- Fixture: FR205 260001 อยู่ในตาราง 2568/1
- ขั้นตอน: เปิดหน้าแนะนำวิชาเสรี → อ่านรีวิว FR205
- คาดหวัง: Sec 260002 ถูกเลือกอัตโนมัติ แต่ปุ่มเพิ่มทั้งวิชายัง disabled และมีข้อความอยู่ในตารางแล้ว
- จริง: radios disabled ทั้งคู่และไม่มีตัวใดถูกเลือก ค่า API ของ 260002 ยังเป็น selectable=true, inTimetable=false; conflictWith ว่างถูกต้อง
- ผลกระทบ: สถานะ selection ต่างจากกติกาที่ออกแบบ การกันวิชาซ้ำยังทำงาน ไม่ใช่ข้อผิดพลาดที่เพิ่มวิชาซ้ำได้
- หลักฐาน: [UI](./evidence/10b-already-added-detail.ax.txt), network caseId `10`, [DB](./evidence/db-before-after.json)
- เกณฑ์ทดสอบซ้ำ: ได้ selection ตาม T15, ปุ่มเพิ่มยัง disabled, ไม่มี POST และ DB ไม่เปลี่ยน

## 2. [P2] แสดงเหตุผลเมื่อเพิ่มวิชาแล้วจะเกินหน่วยกิต

- Label: Maintenance
- เคส: ST-US6-13; เชื่อม T17 IT-26
- Fixture: PY200/PY250/AT326/JC217/AS201/GE225/PB317 รวม 21 หน่วยกิต
- ขั้นตอน: เปิด FR205 Sec 260001 แล้วตรวจ/กดเพิ่ม
- คาดหวังตาม T15: ปุ่มกดได้ ส่ง POST แล้วรับ 409 CREDIT_LIMIT_EXCEEDED; modal คงอยู่และแสดง “เพิ่ม FR205 (3 หน่วยกิต) แล้วจะเป็น 24 หน่วยกิต เกินกำหนด 22 หน่วยกิต”
- จริง: ปุ่ม disabled ตั้งแต่ก่อนส่ง ไม่มี POST และไม่มีเหตุผลเรื่องหน่วยกิตแสดงใน modal
- ผลกระทบ: ผู้ใช้ไม่ทราบเหตุผลที่เพิ่มไม่ได้; backend ป้องกันหน่วยกิตเกินถูกต้อง
- หลักฐาน: [UI](./evidence/13b-credit-limit-disabled.ax.txt), [backend เสริม 409](./evidence/13-api-supplement.json), [DB](./evidence/db-before-after.json)
- เกณฑ์ทดสอบซ้ำ: flow และข้อความตรง T15, ข้อมูลยัง 7 entries และ updated_at ไม่เปลี่ยนหลังถูกปฏิเสธ หากทีมเปลี่ยนกติกาเป็นปิดปุ่ม ต้องยืนยันและปรับแบบทดสอบก่อนตัดสิน PASS

## 3. [P3] ใช้ข้อความโหลดข้อมูลล้มเหลวตามที่ตกลง

- Label: Maintenance
- เคส: ST-US6-16; เชื่อมส่วน network error ของ T17 IT-36 (T19 นี้ไม่ได้รัน detail ถูกลบแบบ IT-33)
- Fixture: ตารางว่าง รายการโหลดครบก่อนเริ่ม
- ขั้นตอน: ตัดเครือข่ายของ GET ค้นหา → ค้นหา → คืนเครือข่ายและลองใหม่; แยกโหลดรายการใหม่แล้วตัด GET detail ของ PY250 → เปิดรายละเอียด → ปิด modal → คืนเครือข่าย
- คาดหวัง: ทั้งรายการและ detail แสดง “ไม่สามารถโหลดข้อมูลวิชาได้ กรุณาลองใหม่อีกครั้ง”
- จริง: รายการใช้ “โหลดวิชาเสรีแนะนำไม่สำเร็จ กรุณาลองใหม่”; detail ใช้ “โหลดรายละเอียดวิชาไม่สำเร็จ กรุณาลองใหม่”
- ผลกระทบ: ข้อความต่างจากข้อตกลง หน้าไม่ค้าง ปิด modal ได้ และกู้คืนได้ จัดเป็นความต่างด้านข้อความ ไม่ใช่ระบบล่ม
- หลักฐาน: [รายการ](./evidence/16b-list-network-failure.ax.txt), [detail](./evidence/16d-detail-network-failure.ax.txt), [กู้คืน](./evidence/16c-list-recovered.ax.txt)
- เกณฑ์ทดสอบซ้ำ: ข้อความตรงที่ตกลง ไม่แสดงการ์ดเก่าปนกับ empty state และค้นหา/เปิด detail ได้อีกเมื่อเครือข่ายกลับมา
