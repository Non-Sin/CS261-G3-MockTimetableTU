# ST-US6-15 — ขั้นตอนที่ยังต้องตรวจโดยตรง

สถานะปัจจุบัน **PARTIAL**: API ไม่มี token/มี token หมดอายุผ่าน 6/6 กรณีแล้ว; browser flow GET/POST รับ 401 จริงแล้วกลับ Login ผ่าน แต่ใช้การถอด Authorization ที่ recorder ไม่ใช่ลบ sessionStorage โดยตรง

เครื่องมือควบคุมหน้าต่าง Windows ยืนยัน URL ไม่ได้และ Chrome connector ไม่พร้อมใช้ จึงไม่อ้างว่าทำขั้นตอนด้านล่างแล้ว ระบบ Docker ทดสอบรอบนี้ปิดเรียบร้อย ต้องเปิดฐานทดสอบแยกใหม่ก่อนทำซ้ำ

## GET หลังลบ token

1. เปิดระบบจริง profile `stub-tu` และฐานทดสอบแยก เตรียมบัญชี `6609000001` ให้ตารางว่าง
2. Login ผ่านหน้าเว็บ เปิด “ดูวิชาเสรีแนะนำ” และรอรายการโหลดเสร็จ
3. เปิด DevTools → Console แล้วรันเฉพาะการลบ token ทดสอบ:

   ```js
   sessionStorage.removeItem("mocktimetable.auth.token")
   ```

4. กด “ค้นหาวิชา” ต้องกลับ Login และไม่มีรายการเก่าค้าง
5. เก็บภาพหรือ DOM/Network log และตรวจว่า DB ยังไม่มี timetable ของบัญชีนี้

## POST หลังลบ token

1. Login ใหม่ เปิดรายการและอ่านรีวิว FR205 รอรายละเอียดโหลดเสร็จ
2. ลบ token ด้วยคำสั่งเดิม แล้วกด “+ เพิ่มลงตาราง”
3. ต้องกลับ Login และ modal ไม่ค้าง ตรวจว่าไม่มี entry ใหม่ใน DB
4. เก็บหลักฐานและผลจริงของทั้งสองขั้นตอนก่อนปรับสถานะเคส 15

หาก client ตรวจ token ที่หายก่อนส่ง request จนไม่มี HTTP request ออก ให้บันทึกตามจริง ไม่กำหนดว่าต้องเห็น backend 401 ในขั้นตอน UI นี้เสมอ ฝั่ง API 401 ถูกตรวจแยกไว้แล้ว
