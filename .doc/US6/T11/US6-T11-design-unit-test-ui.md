# US6-T11: Design Unit Test Cases ส่วน UI

## User Story
**US6:** ดูวิชาเสรีแนะนำ

## Objective
ออกแบบ Unit Test Cases สำหรับ UI ของ US6 เพื่อทดสอบการทำงานของช่องค้นหา, ตัวกรองข้อมูล (รวมถึงการใช้หลายตัวกรองพร้อมกัน), การ์ดรายละเอียดวิชาและ Modal (รวมถึงการเลือก Section เริ่มต้นอัตโนมัติและการปิดการเลือก Section ต่างภาคเรียน), ปุ่มเพิ่มลงตาราง (รวมถึงการปิดปุ่มเมื่อหน่วยกิตเกิน 22 หน่วยกิต และการแจ้งเตือนเวลาเรียนชน), และการจัดการกรณีไม่พบวิชา

## Scope
ครอบคลุม Conditions of Satisfaction (CoS) ของ US6 และข้อกำหนดร่วมกับ US6-T05 / US6-T06 ดังนี้:
- Test Case 1: ผู้ใช้สามารถค้นหารายวิชาเสรีแนะนำด้วยรหัสวิชาหรือชื่อวิชาได้
- Test Case 2: ผู้ใช้สามารถกรองรายวิชาตามวันเรียน, ช่วงเวลา, หมวดหมู่, และภาคเรียน รวมถึงกรองเฉพาะวิชาที่ไม่ชนกับตารางปัจจุบัน
- Test Case 3: ระบบแสดงรายละเอียดวิชาและรีวิวจากรุ่นพี่ได้อย่างถูกต้อง โดยเมื่อเปิด Modal ระบบจะเลือก Sec แรกที่เลือกได้ให้อัตโนมัติ และปิดการเลือก Sec ของภาคเรียนอื่น
- Test Case 4: ผู้ใช้สามารถกดเพิ่มวิชาลงตารางเรียนจำลองได้ โดยปุ่มเพิ่มลงตารางจะถูกปิดใช้งาน (`disabled`) หากหน่วยกิตรวมเกิน 22 หน่วยกิต (ไม่มีข้อความแจ้งเตือนหน่วยกิตเกินบน UI ของหน้าค้นหา/เลือกวิชา) และระบบจะแสดงข้อความเตือนหากเวลาเรียนซ้อนทับกับตารางปัจจุบัน
- Test Case 5: กรณีค้นหาไม่พบข้อมูลวิชา ระบบต้องแสดง Empty State ที่เหมาะสม

## Test Approach
- ออกแบบ Unit Test Cases โดยอ้างอิงจาก User Story, CoS, UI Prototype และเอกสารออกแบบ US6-T05 / US6-T06
- ทดสอบที่ระดับ Component / Function โดยใช้ Mock Data สำหรับรายวิชาเสรีและตารางเรียนจำลอง
- **Mock การทำงานของฟังก์ชันจัดการตารางเรียน** เช่น `ScheduleOverlap` และคำนวณหน่วยกิตรวม เพื่อจำลองสถานการณ์ที่หน่วยกิตเกิน (ปุ่ม `disabled`) หรือเวลาเรียนซ้อนทับ (แสดง Alert)
- เครื่องมือที่เสนอ: Vitest + React Testing Library
- ภาคเรียนที่ใช้ทดสอบคือภาคการศึกษา 1/2568 และ 2/2568 ตามข้อมูล Seed Data ของระบบ

## Test Cases

### [UT-UI-US6-01] ค้นหารายวิชาเสรีแนะนำด้วยรหัสหรือชื่อวิชา

**Related CoS:** Test Case 1

**Preconditions:**
- Render หน้าจอแนะนำวิชาเสรีพร้อมส่วนค้นหา

**Test Data:**
- ค้นหาด้วยรหัส: `"FR205"`
- ค้นหาด้วยชื่อ: `"PSYCHOLOGY"`

**Test Steps:**
1. พิมพ์คำค้นหาลงในช่องค้นหา
2. ตรวจสอบผลลัพธ์การแสดงผลการ์ดรายวิชา

**Expected Result:**
- ค้นหาด้วย `"FR205"`: แสดงการ์ดวิชา FR205 ถูกต้อง
- ค้นหาด้วย `"PSYCHOLOGY"`: แสดงการ์ดวิชา PY250 ถูกต้อง
- ระบบกรองข้อมูลตามอินพุตที่ผู้ใช้พิมพ์ได้อย่างถูกต้อง

---

### [UT-UI-US6-02] กรองรายวิชาตามเงื่อนไขและใช้งานหลายตัวกรองพร้อมกัน

**Related CoS:** Test Case 2

**Preconditions:**
- Render หน้ารายวิชาเสรีที่มีชุดข้อมูลจำลองหลายรายวิชา

**Test Data:**
- ตัวกรองวันเรียน: `"วันจันทร์"`
- ตัวกรองพิเศษ: `"แสดงเฉพาะวิชาที่ไม่ชนกับตารางปัจจุบัน"` (เปิดใช้งาน)

**Test Steps:**
1. เลือกตัวกรองวันเรียนเป็น "วันจันทร์"
2. เปิดใช้งานตัวกรอง "แสดงเฉพาะวิชาที่ไม่ชนกับตารางปัจจุบัน" พร้อมกัน
3. ตรวจสอบรายวิชาที่แสดงผลบนหน้าจอ

**Expected Result:**
- ผลลัพธ์แสดงเฉพาะรายวิชาที่เรียนวันจันทร์ **และ** ไม่มีเวลาเรียนทับซ้อนกับตารางเรียนปัจจุบันของผู้ใช้
- ระบบรองรับการทำงานของ Multi-filters ได้อย่างถูกต้อง

---

### [UT-UI-US6-03] แสดงรายละเอียดวิชาและรีวิวใน Modal พร้อมเลือก Sec อัตโนมัติและปิดการเลือก Sec ต่างภาคเรียน

**Related CoS:** Test Case 3 (อ้างอิง US6-T06 Sequence Diagram: Detail & AddEntry)

**Preconditions:**
- Render การ์ดรายวิชาที่มีหลาย Section และมี Section ของต่างภาคเรียน (เช่น วิชา PY250 ที่มีทั้ง Sec ในภาคปัจจุบัน `selectable: true` และ Sec ของอีกภาคเรียน `selectable: false`)

**Test Data:**
- ข้อมูลรายละเอียด, รีวิว และรายการ Sections ของวิชา PY250 หรือ FR205

**Test Steps:**
1. คลิกที่การ์ดรายวิชาเพื่อเปิด Modal รายละเอียด
2. ตรวจสอบสถานะการเลือก Section เริ่มต้นทันทีที่เปิด Modal
3. ตรวจสอบสถานะของ Section ที่เปิดสอนในอีกภาคเรียน (`selectable: false`)
4. ลองคลิกเปลี่ยนไปเลือก Section อื่นที่อยู่ในภาคเรียนปัจจุบัน

**Expected Result:**
- Modal แสดงข้อมูลกลุ่มเรียน (Sections), ตารางเรียน, ห้องเรียน, และรีวิวจากรุ่นพี่ครบถ้วน
- **ทันทีที่เปิด Modal ระบบจะเลือก Sec แรกที่สามารถเลือกได้ (`selectable && !inTimetable`) ตามลำดับ `semester` และ `sectionNo` ให้อัตโนมัติทันที** (แม้จะมีหลายตัวเลือก)
- **Sec ของอีกภาคเรียน (`selectable: false`) จะอยู่ในสถานะปิดการใช้งาน ไม่สามารถกดเลือกได้**
- ผู้ใช้สามารถสลับเลือก Sec อื่นภายในภาคเรียนปัจจุบันได้ตามปกติ และสามารถปิด Modal ได้เมื่อคลิกปุ่มกากบาทหรือพื้นที่นอก Modal

### [UT-UI-US6-04] คลิกปุ่มเพิ่มลงตารางสำเร็จเมื่อไม่มีข้อผิดพลาด

**Related CoS:** Test Case 4

**Preconditions:**
- เปิด Modal รายละเอียดวิชา (เช่น FR205) ที่ไม่มีเวลาชนและหน่วยกิตรวมไม่เกิน 22 หน่วยกิต (มี Sec ที่ถูกเลือกอัตโนมัติไว้แล้ว)

**Test Data:**
- วิชา FR205 (3 หน่วยกิต, วันอังคาร/พฤหัสบดี 16:30 - 18:00)

**Test Steps:**
1. ตรวจสอบสถานะปุ่มเพิ่มลงตารางและคลิกปุ่มเพิ่มลงตาราง

**Expected Result:**
- ปุ่มเพิ่มลงตารางสามารถกดได้ (Enabled)
- ระบบเรียกใช้งาน Handler เพื่อเพิ่มวิชาลงในตารางเรียนจำลอง และแสดงสถานะว่าเพิ่มวิชาสำเร็จ

---

### [UT-UI-US6-05] แสดงข้อความเตือนเมื่อเวลาเรียนชนกับตารางปัจจุบัน

**Related CoS:** Test Case 4

**Preconditions:**
- เปิด Modal รายละเอียดวิชาที่มีเวลาเรียนทับซ้อนกับตารางปัจจุบัน (เช่น วิชา PY250 เรียนวันจันทร์ 13:30 - 16:30 ซึ่งมี `conflictWith` ไม่ว่าง) และหน่วยกิตรวมยังไม่เกิน 22

**Test Data:**
- วิชา PY250 (เวลาเรียนชนกัน)

**Test Steps:**
1. คลิกปุ่มเพิ่มลงตาราง
2. ตรวจสอบการแจ้งเตือนบน UI

**Expected Result:**
- ระบบยังอนุญาตให้กดเพิ่มลงตารางได้ตามกติกา US1 และแสดงข้อความเตือน (Warning Alert) บนหน้าจอเรื่องเวลาเรียนซ้อนทับอย่างชัดเจน

---

### [UT-UI-US6-06] ปิดการใช้งานปุ่มเพิ่มลงตารางเมื่อหน่วยกิตรวมเกิน 22 หน่วยกิต (ไม่แสดงข้อความเตือน)

**Related CoS:** Test Case 4 (ซิงค์กับ US6-T05 / US6-T13 เคส `IT-UI-API-US6-26`)

**Preconditions:**
- จำลองสถานะตารางเรียนปัจจุบันที่มีหน่วยกิตสะสมอยู่แล้ว 21 หน่วยกิต
- เปิด Modal รายละเอียดวิชาที่มีขนาด 3 หน่วยกิต (ซึ่งจะทำให้หน่วยกิตรวมเป็น 24 หน่วยกิต เกินลิมิต 22)

**Test Data:**
- วิชาขนาด 3 หน่วยกิต (เช่น FR205)

**Test Steps:**
1. ตรวจสอบสถานะของปุ่มเพิ่มลงตาราง และพื้นที่แสดงผลข้อความแจ้งเตือนบนหน้าจอ
2. พยายามคลิกปุ่มเพิ่มลงตาราง

**Expected Result:**
- ปุ่มเพิ่มลงตารางอยู่ในสถานะปิดการใช้งาน (`disabled`) ไม่สามารถกดเพิ่มวิชาได้ (ตรงกับสถานะการตรวจสอบใน Integration Test `IT-UI-API-US6-26`)
- หน้าเว็บ **ไม่แสดง** ข้อความแจ้งเตือนเรื่องหน่วยกิตเกินล่วงหน้าบน UI
- Handler สำหรับเพิ่มวิชาไม่ถูกเรียกใช้งาน

---

### [IT-UI-API-US6-26] Integration Test: ซิงค์สถานะปุ่มเพิ่มลงตารางเมื่อหน่วยกิตรวมเกิน 22 หน่วยกิต

**Related Spec:** US6-T05 / US6-T13 (ซิงค์เงื่อนไขร่วมกับ `UT-UI-US6-06`)

**Preconditions:**
- จำลองการเชื่อมต่อข้อมูลตารางเรียนปัจจุบันที่มีหน่วยกิตรวมสะสม 21 หน่วยกิต และโหลดรายละเอียดวิชาขนาด 3 หน่วยกิต

**Test Data:**
- วิชาขนาด 3 หน่วยกิต (ทำให้หน่วยกิตรวมเป็น 24 หน่วยกิต เกินลิมิต 22)

**Test Steps:**
1. เปิด Modal รายละเอียดวิชาและตรวจสอบสถานะของปุ่มเพิ่มลงตารางที่เชื่อมโยงกับ State ของตารางเรียน

**Expected Result:**
- ปุ่มเพิ่มลงตารางถูกตั้งค่าเป็น `disabled` ทันทีเมื่อคำนวณแล้วพบว่าหน่วยกิตรวมจะเกิน 22 หน่วยกิต และไม่เรียก API `POST /api/timetable/entries` (พฤติกรรมตรงกันทั้งฝั่ง Unit Test UI และ Integration Test)

---

### [UT-UI-US6-07] ค้นหาไม่พบข้อมูลวิชา แสดง Empty State

**Related CoS:** Test Case 5

**Preconditions:**
- Render หน้าจอแนะนำวิชาเสรี

**Test Data:**
- ค้นหารหัสวิชาที่ไม่มีในระบบ: `"SA240"`

**Test Steps:**
1. พิมพ์คำว่า `"SA240"` ในช่องค้นหาแล้วกดค้นหา

**Expected Result:**
- ระบบแสดงผลลัพธ์เป็น 0 วิชา
- แสดง Component ส่วน Empty State พร้อมข้อความ *"ไม่พบรีวิววิชานี้"* หรือข้อความแจ้งเตือนว่าไม่พบข้อมูล พร้อมปุ่มรีเซ็ตหรือดูวิชาทั้งหมด
