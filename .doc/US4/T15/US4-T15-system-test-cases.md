## 1. แนวทางและสภาพแวดล้อม

System test ทดสอบ **ทั้งระบบต่อกันตั้งแต่หน้าเว็บ ผ่าน API ไปถึงฐานข้อมูล** ตามลำดับใน Sequence Diagram ของ US4-T06 ไม่ใช่ทดสอบทีละชั้นเหมือน Unit และ Integration Test

| Flow | ที่มา | สรุป |
| --- | --- | --- |
| 1. Logout | T06 | กด "ออกจากระบบ" (ปุ่มอยู่ที่ Navbar มุมขวาบนของทุกหน้า) → `POST /api/auth/logout` (Bearer, ไม่มี body) → `204` → UI ล้าง authentication state → กลับหน้า Login ถ้า token ใช้ไม่ได้ได้ `401` และ UI ทำผลเหมือนเดิม |
| 2. Session หมดอายุ | T06 | ผู้ใช้ไม่เรียก Logout API ฝั่ง UI พบ `401` จาก API ใดก็ได้ที่ต้อง Authentication → ล้าง state → กลับหน้า Login พร้อม banner สีเหลืองแจ้งว่า Session หมดอายุ |

ข้อกำหนดที่ใช้

- `POST /api/auth/logout` ตอบ `204 No Content` (ไม่มี body) และตอบ `401 Unauthorized` เป็น ProblemDetail เมื่อ token หมดอายุหรือผิด
- US4 **ไม่มี DAO, entity หรือ DB operation ใหม่** Logout และการตรวจ Session หมดอายุไม่อ่านหรือเขียนตารางใดเลย ผลที่ตรวจใน DB จึงเป็น "ไม่เปลี่ยน"
- **ระบบเป็น stateless ไม่มี blacklist** token ที่ออกให้แล้วยังใช้ได้ทางเทคนิคจนหมดอายุ แม้ผู้ใช้ logout ไปแล้ว นี่คือ **ข้อจำกัดของระบบ** ที่บันทึกไว้ใน US4-T05 API Spec แล้ว (ดู ST-10, ST-20)
- **อายุของ token คือ 3 ชั่วโมง**
- การล้าง authentication state ฝั่ง Client ทำทั้งกรณี `204` และ `401` และประกอบด้วย 3 อย่าง
  1. ลบ token ออกจาก localStorage และ sessionStorage
  2. ล้างข้อมูลผู้ใช้ใน React Auth Context/State
  3. ล้าง cache ข้อมูลตารางเรียน
- **banner "เซสชันของคุณหมดอายุแล้ว กรุณาเข้าสู่ระบบใหม่อีกครั้ง"** (สีเหลือง บนหน้า Login) แสดงเฉพาะกรณี Session หมดอายุ **ไม่แสดง** เมื่อผู้ใช้กด logout เอง แม้ตอนนั้น token หมดอายุไปแล้ว (ถือเป็น logout สำเร็จตามปกติ)

สภาพแวดล้อม

- รัน frontend, backend (Spring Boot) และฐานข้อมูลทดสอบจริงทั้งชุด
- ตรวจ request/response ด้วย DevTools tab Network, ตรวจที่เก็บ token ด้วย tab Application และยิง API ตรงด้วย Postman
- **TU Login API จำลอง (stub)** เหมือน US3-T13 เพราะเป็นระบบภายนอก
- token จริงอายุ 3 ชั่วโมง การทดสอบหมดอายุจึงต้องย่ออายุ token ในสภาพแวดล้อมทดสอบ (เช่น 1–2 นาที) หรือใช้ token ที่ออกให้หมดอายุไปแล้ว ดูหัวข้อ 3.2
