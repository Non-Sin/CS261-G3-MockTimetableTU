# US4-T11 Design Unit Test Cases ส่วน UI
## User Story
US4: Logout / ออกจากระบบ

## Objective
ออกแบบ Unit Test Cases สำหรับ UI ของ US4 เพื่อทดสอบการทำงานของปุ่ม Logout การแสดงหน้า Login หลังออกจากระบบ การกดย้อนกลับหลัง Logout และการ Logout อัตโนมัติเมื่อ Session หมดอายุ

## Scope
ครอบคลุมการทดสอบ UI ดังนี้
- Test Case 1: การกดปุ่ม Logout
- Test Case 2: การกลับไปหน้า Login หลัง Logout
- Test Case 3: การกดย้อนกลับหลัง Logout
- Test Case 4: การ Logout อัตโนมัติ

## Test Approach
- ออกแบบ Unit Test Cases โดยอ้างอิงจาก User Story, CoS และ UI Prototype จาก Google Stitch
- ใช้การจำลองผลลัพธ์ของการ Logout และสถานะการเข้าสู่ระบบ รวมถึงเหตุการณ์ Session หมดอายุ เพื่อทดสอบพฤติกรรมของ UI โดยไม่จำเป็นต้องเชื่อมต่อ Backend จริง
- ทดสอบการแสดงผลและพฤติกรรมการโต้ตอบของ UI เป็นหลัก
- ยังไม่ได้ดำเนินการทดสอบจริง เนื่องจาก Frontend อยู่ระหว่างพัฒนา
- ชื่อ Component และวิธี Mock อาจปรับเปลี่ยนตาม Implementation จริง

## Test Cases
### [UT-UI-01] ทดสอบการกดปุ่ม Logout
Related CoS: Test Case 1
Preconditions:
- UI ส่วนที่เกี่ยวข้องกับการ Logout พร้อมสำหรับการทดสอบ
- ผู้ใช้อยู่ในสถานะเข้าสู่ระบบแล้ว
- สามารถจำลองผลลัพธ์ของการ Logout ได้
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

Test Data:
- สถานะผู้ใช้: `Authenticated`
- ผลลัพธ์การ Logout ที่จำลอง: `Success`
<!-- อาจต้องแก้ไข: ชื่อปุ่มและวิธีจำลองผลลัพธ์ให้ตรงกับ UI Prototype และ Implementation จริง -->

Test Steps:
1. Render UI ด้วยสถานะผู้ใช้ที่เข้าสู่ระบบแล้ว
2. ตรวจสอบว่ามีปุ่ม Logout แสดงอยู่บน UI
3. จำลองการคลิกปุ่ม Logout
4. ตรวจสอบว่าระบบเรียกการทำงาน Logout

Expected Result:
- UI แสดงปุ่ม Logout เมื่อผู้ใช้เข้าสู่ระบบแล้ว
- เมื่อผู้ใช้คลิกปุ่ม Logout ระบบเรียกการทำงาน Logout
- การทำงาน Logout ถูกเรียกตามจำนวนครั้งที่กำหนดในการทดสอบ
- UI ตอบสนองต่อการคลิกตามพฤติกรรมที่ออกแบบไว้

### [UT-UI-02] ทดสอบการแสดงหน้า Login หลัง Logout สำเร็จ
Related CoS: Test Case 1
Preconditions:
- UI หน้า Login พร้อมสำหรับการทดสอบ
- ผู้ใช้อยู่ในสถานะเข้าสู่ระบบแล้ว
- สามารถจำลองผลลัพธ์การ Logout สำเร็จได้
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

Test Data:
- สถานะก่อน Logout: `Authenticated`
- ผลลัพธ์การ Logout: `Success`
- หน้าปลายทางที่คาดหวัง: `Login`
<!-- อาจต้องแก้ไข: ยืนยันหน้าปลายทางและชื่อ Route ให้ตรงกับการออกแบบจริงของระบบ -->

Test Steps:
1. Render UI ด้วยสถานะผู้ใช้ที่เข้าสู่ระบบแล้ว
2. จำลองการกดปุ่ม Logout
3. จำลองให้การ Logout สำเร็จ
4. ตรวจสอบหน้าที่ UI แสดงหลัง Logout สำเร็จ

Expected Result:
- UI เปลี่ยนไปยังหน้า Login หลัง Logout สำเร็จ
- UI ไม่แสดงข้อมูลที่ต้องเข้าสู่ระบบก่อนจึงจะเข้าถึงได้
- UI แสดงองค์ประกอบของหน้า Login ตามที่ออกแบบไว้

### [UT-UI-03] ทดสอบการกดย้อนกลับหลัง Logout
Related CoS: Test Case 2
Preconditions:
- ผู้ใช้ Logout สำเร็จแล้ว
- UI แสดงหน้า Login
- สามารถจำลองสถานะผู้ใช้หลัง Logout ได้
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

Test Data:
- สถานะผู้ใช้หลัง Logout: `Unauthenticated`
- หน้าปัจจุบัน: `Login`
- การกระทำ: `Browser Back`

Test Steps:
1. จำลองให้ผู้ใช้เข้าสู่ระบบและเข้าถึงหน้าที่ต้องเข้าสู่ระบบ
2. จำลองการ Logout จนกลับมาหน้า Login
3. จำลองการกดย้อนกลับ
4. ตรวจสอบหน้าที่แสดงหลังจากกดย้อนกลับ
5. ตรวจสอบสถานะผู้ใช้และการเข้าถึงหน้าที่ต้องเข้าสู่ระบบ

Expected Result:
- สถานะผู้ใช้ยังคงเป็น `Unauthenticated` หลัง Logout
- ผู้ใช้ไม่สามารถเข้าถึงหน้าที่ต้องเข้าสู่ระบบได้โดยไม่มีการยืนยันตัวตน
- UI แสดงหน้า Login หรือหน้าอื่นที่อนุญาตให้เข้าถึงได้ตามข้อกำหนดของระบบ

### [UT-UI-04] ทดสอบการ Logout อัตโนมัติเมื่อไม่มีการใช้งานเกินระยะเวลาที่กำหนด
Related CoS: Test Case 3
Preconditions:
- UI ที่รองรับสถานะ Session หมดอายุพร้อมสำหรับการทดสอบ
- ผู้ใช้อยู่ในสถานะเข้าสู่ระบบแล้ว
- สามารถจำลองระยะเวลาที่ไม่มีการใช้งานเกินกำหนดได้
- ไม่จำเป็นต้องเชื่อมต่อ Backend จริง

Test Data:
- สถานะก่อน Session หมดอายุ: `Authenticated`
- สถานะหลัง Session หมดอายุ: `Unauthenticated`
- เหตุการณ์ที่จำลอง: ไม่มีการใช้งานเกินระยะเวลาที่กำหนด


Test Steps:
1. Render UI ด้วยสถานะผู้ใช้ที่เข้าสู่ระบบแล้ว
2. จำลองการไม่มีการใช้งานเกินเวลาที่กำหนด
3. ตรวจสอบว่าระบบดำเนินการ Logout อัตโนมัติ
4. ตรวจสอบหน้าที่ UI แสดงหลัง Logout สำเร็จ
5. ตรวจสอบสถานะผู้ใช้หลังจากเหตุการณ์เสร็จสิ้น

Expected Result:
- UI ตอบสนองต่อเหตุการณ์ Session หมดอายุ
- ระบบเปลี่ยนสถานะผู้ใช้เป็น `Unauthenticated`
- UI นำผู้ใช้กลับไปหน้า Login หรือหน้าที่กำหนดไว้สำหรับ Session หมดอายุ
- ผู้ใช้ไม่สามารถเข้าถึงหน้าที่ต้องเข้าสู่ระบบได้โดยไม่มีการยืนยันตัวตน
<!-- หากระบบกำหนดให้แจ้งเตือนก่อนหมดอายุ แสดงข้อความ Session หมดอายุ หรือให้ผู้ใช้เข้าสู่ระบบใหม่ ให้เพิ่ม Expected Result ตามข้อกำหนดจริง -->

## หมายเหตุ
- เอกสารนี้เป็นการออกแบบ Test Cases เบื้องต้น ยังไม่ได้ดำเนินการทดสอบจริง
- ข้อความที่อยู่ในคอมเมนต์ HTML เป็นจุดที่ต้องตรวจสอบกับ UI Prototype ของ T05 ก่อนอีกครั้ง
- Test Cases นี้เน้นพฤติกรรมของ UI โดยใช้การจำลองผลลัพธ์ที่เกี่ยวข้อง ไม่ได้ทดสอบการทำงานของ Backend จริง
- การตรวจสอบสถานะ Session และการป้องกันการเข้าถึงหน้าหลัง Logout อาจต้องอาศัยการทดสอบร่วมกับ Logic หรือ Integration Test เพิ่มเติม ขึ้นอยู่กับการแบ่งส่วนการทำงานของระบบจริง
