## 1. แนวทางและสภาพแวดล้อม

Integration test ระหว่าง UI กับ API ตรวจว่า **หน้าเว็บกับ backend คุยกันถูกต้องจริง** ไม่ใช่แค่ component ทำงานได้ตามที่จำลอง (T11) หรือ API ตอบถูกเมื่อยิงตรง (T14/T15) สิ่งที่ตรวจในแต่ละ case คือ 3 ชั้นต่อกัน:

1. **สิ่งที่ UI ส่ง** (method, path, header, body)
2. **สิ่งที่ API ตอบ** (status, `code`, โครงสร้าง ProblemDetail)
3. **สิ่งที่ UI แสดงหลังรับคำตอบ** (หน้าที่แสดง, การเก็บ token, การเรียก API ต่อ)

สภาพแวดล้อม

- รัน frontend จริงชี้ไปที่ backend (Spring Boot) จริง ฐานข้อมูลสำหรับทดสอบ
- **TU Login API ต้องจำลอง (stub)** เพราะเป็นระบบภายนอกของมหาวิทยาลัย ทดสอบกับของจริงไม่ได้ (บัญชีจริง, ถูกล็อกจริง, เปลี่ยนรหัสจริง) stub ตอบตาม fixture ในหัวข้อ 3 ผ่าน `TuApiClient.verifyCredentials(username, password)`
- ตั้งค่า `LOCK_TIME_DURATION` ของ `LoginAttemptService` ให้สั้นลงในสภาพแวดล้อมทดสอบ (T06 กำหนดให้อ่านจาก configuration) เพื่อไม่ต้องรอ 15 นาทีจริง
- ใช้ตรวจด้วยเบราว์เซอร์ (หรือเครื่องมือ E2E) ร่วมกับดู request/response ใน DevTools tab Network

## 2. สัญญาระหว่าง UI กับ API (สรุปจาก API Spec และ T06)

| | ค่า |
| --- | --- |
| Request | `POST /api/auth/login` · `Content-Type: application/json` · body `{ "username": "...", "password": "..." }` |
| สำเร็จ | `200 { "token": "..." }` |
| Error | ProblemDetail (`type`, `title`, `status`, `detail`, `instance`) + `code` (+ `retryAfterSeconds` เฉพาะ 429) |

| `code` | HTTP | เกิดเมื่อ | UI แสดง |
| --- | --- | --- | --- |
| `INVALID_CREDENTIALS` | 401 | TU Login API แจ้งว่า Username หรือ Password ผิด (ครั้งที่ 1–4) | กล่องแจ้งเตือนรหัสผิดในฟอร์ม (Prototype) |
| `ACCOUNT_INACTIVE` | 403 | บัญชี มธ. ไม่ Active | **หน้าจอเดียวกับ `INVALID_CREDENTIALS` ทุกประการ** (ข้อสรุป หัวข้อ 4.1 ข้อ 1) |
| `NOT_CS_STUDENT` | 403 | department ไม่ใช่ CS หรือ track ไม่ใช่ภาคปกติ | หน้า "ไม่สามารถเข้าใช้งานระบบได้" (Prototype) |
| `ACCOUNT_LOCKED` | 429 | ผิดครบ 5 ครั้ง หรือยังถูกระงับอยู่ | หน้า "ระงับการเข้าสู่ระบบชั่วคราว" พร้อมตัวนับถอยหลัง (Prototype) |

ลำดับการตรวจของ `AuthService.authenticate` ที่ใช้กำหนดผลที่คาดหวัง (ตาม Sequence Diagram ของ T06)

1. ตรวจ body (`username`, `password` ไม่ว่าง `@NotBlank`) → `400` ProblemDetail พร้อม `errors` **ไม่ยิง TU Login API**
2. ตรวจว่าถูกระงับอยู่หรือไม่ → ถ้าใช่ `429` ทันที **ไม่ยิง TU Login API**
3. ตรวจรหัสผ่านกับ TU → ผิด: นับครั้ง แล้ว `401` (ถ้านับแล้วครบ 5 ได้ `429` พร้อม `retryAfterSeconds: 900` เลย)
4. รหัสถูก: ล้างจำนวนครั้งที่ผิด (`REQUIRES_NEW` จึงไม่ถูก rollback แม้ขั้นถัดไปจะได้ 403)
5. บัญชีไม่ Active → `403 ACCOUNT_INACTIVE` · ไม่ใช่ CS ภาคปกติ → `403 NOT_CS_STUDENT`
6. บันทึกผู้ใช้ (Upsert ตาราง `users`) แล้วสร้าง JWT ตอบ `200`

หลังได้ token UI เรียก `GET /api/users/me` ส่ง `Authorization: Bearer <token>` ตอบ `200 { studentId, firstName, lastName }` แล้วพาไป**หน้าเมนูหลัก**และแสดงชื่อ-รหัสที่ Navbar (ไม่มีหน้ากรอกประวัติ ดูหัวข้อ 4.1 ข้อ 2)
