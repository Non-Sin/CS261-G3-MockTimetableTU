## 1. ขอบเขตและแนวทางการทดสอบ
Integration Test ระหว่าง UI กับ API ตรวจการทำงานร่วมกัน 3 ชั้นต่อกันในทุก test case:

1. **สิ่งที่ UI ส่ง** (HTTP method, path, query parameters, request body, header `Authorization: Bearer <token>`)

2. **สิ่งที่ API ตอบ** (HTTP status code, JSON body หรือ `ProblemDetail`)

3. **สิ่งที่ UI แสดงผล** (รายการวิชาที่จะเพิ่ม, รายการวิชาที่ข้ามพร้อมเหตุผล, ข้อความ Empty State, Loading, ข้อความ Error, และตารางเรียนหลังยืนยัน)

กลุ่มทดสอบหลัก 3 กลุ่มตามที่ได้รับมอบหมาย:

- **กลุ่ม A — หน้าเว็บเรียก API ดูสรุปแล้วยืนยัน** (`dryRun: true` อัตโนมัติเมื่อเลือกเงื่อนไขครบ แล้วกดยืนยันผ่านปุ่ม "เพิ่มลงตารางเรียน" ด้วย `dryRun: false`)

- **กลุ่ม B — ยืนยันโดยมีบางวิชาที่เพิ่มไม่ได้** (วิชาที่ข้ามอยู่ใน `skipped` ส่วนวิชาอื่นยังถูกเพิ่ม ไม่ fail ทั้งชุด)

- **กลุ่ม C — API ตอบ error แล้วหน้าเว็บแสดงข้อความถูกต้อง**

### Endpoints ที่หน้าเว็บเรียก
| ลำดับ | Method & Path | จุดที่หน้าเว็บเรียกใช้ | Test Cases |
| --- | --- | --- | --- |
| 1 | `GET /api/study-plans?studyYear={1-4}&semester={1-2}` | เลือกชั้นปี / ภาคเรียน เพื่อโหลดแผนการเรียน (`plans`) และวิชาโท (`minors`) | `IT-US8-01` – `IT-US8-05`, `IT-US8-27` – `IT-US8-29`, `IT-US8-31`, `IT-US8-34` |
| 2 | `POST /api/timetable/apply-plan` (`dryRun: true`) | เรียกอัตโนมัติทันทีเมื่อเลือกเงื่อนไขครบ เพื่อโหลดรายการวิชาที่จะลงตารางก่อนบันทึก | `IT-US8-06` – `IT-US8-15`, `IT-US8-22`, `IT-US8-23` – `IT-US8-26`, `IT-US8-30`, `IT-US8-32` |
| 3 | `POST /api/timetable/apply-plan` (`dryRun: false`) | คลิกปุ่ม "เพิ่มลงตารางเรียน" ด้านล่าง Modal เพื่อบันทึกลงตารางจริง | `IT-US8-16` – `IT-US8-22`, `IT-US8-30`, `IT-US8-33` |

### สภาพแวดล้อม
- รัน frontend (Next.js) จริง ชี้ไปยัง backend (Spring Boot) และฐานข้อมูล SQL Server จริงที่มี seed ของ US1, US3 และ US8 (preset แผนการเรียน / วิชาโทตามหลักสูตร CS TU)
- เข้าสู่ระบบด้วย JWT จริงผ่าน `Authorization: Bearer <token>` (US3)
- ตรวจ Network request/response ผ่าน Playwright หรือ DevTools tab Network
- กรณี Error ที่ไม่เกิดจากการกด UI ปกติ (400, 401, 404 ของ `planId`/`minorId`, 500, Offline) ใช้การดัก/จำลอง response (เช่น Playwright `page.route`) ส่วนกรณีที่ต้องการตรวจ contract ของ API ล้วน ๆ ให้ยิง request ตรงด้วยเครื่องมือ HTTP

## 5. ข้อกำหนดและการยืนยันผลการออกแบบกับทีม (Confirmed Requirements)
รายละเอียดด้านล่างได้รับการตรวจสอบและยืนยันร่วมกับทีมพัฒนา Frontend (`CurriculumPlanModal.tsx`, `useCurriculumPlan.ts`) และ API Spec (US8-T05) เรียบร้อยแล้ว:
| # | หัวข้อ | ผลการยืนยันและการนำไปใช้ใน Test Cases |
| --- | --- | --- |
| 1 | **ข้อความ Error ของหน้าเว็บ** | ยืนยันใช้ข้อความภาษาไทยตามที่ระบุในกลุ่ม C ทุกเคส (`IT-US8-23` ถึง `IT-US8-33`) เช่น 400 กฎวิชาโท, 400 validation, 404 ไม่พบแผน, 500 และ Network Offline โดยไม่ใช้คำว่า "(ข้อเสนอ)" อีกต่อไป |
| 2 | **การเรียก `dryRun: true` และชื่อปุ่ม** | • หน้าเว็บเรียก `POST /api/timetable/apply-plan` (`dryRun: true`) **อัตโนมัติทันที** ด้วย `useEffect` เมื่อผู้ใช้เลือกข้อมูลครบ (ชั้นปี 1–2: เลือกชั้นปี + ภาคเรียนครบ / ชั้นปี 3–4: เลือกชั้นปี + ภาคเรียน + แผนการศึกษาครบ และเรียกซ้ำอัตโนมัติเมื่อเปลี่ยนวิชาโท) โดย**ไม่มีปุ่ม "ดูสรุป" แยกต่างหาก** (`useCurriculumPlan.ts`)<br>• ปุ่มยืนยันด้านล่าง Modal ใช้ชื่อปุ่มว่า **"เพิ่มลงตารางเรียน"** (`CurriculumPlanModal.tsx`) |
| 3 | **พฤติกรรม UI เมื่อ `added` ว่าง (`added: []`)** | • ในส่วน "รายวิชาที่จะเพิ่มลงตาราง (0 วิชา)" หน้าเว็บแสดงข้อความ **"ไม่มีวิชาที่เพิ่มลงตารางได้ในแผนนี้"** (`IT-US8-12`)<br>• ปุ่ม **"เพิ่มลงตารางเรียน" ยังคงกดได้ (ไม่ได้ disable)** (`IT-US8-12`, `IT-US8-19`) และเมื่อกดจะไม่เกิดการเขียน DB (`updatedAt` ไม่เปลี่ยน) |
| 4 | **ข้อความของวิชาที่ข้าม (`skipped`)** | ยืนยันว่า UI แสดงผลข้อความแจ้งเตือนตามฟิลด์ `message` ของ API โดยตรง (ตรงตาม `IT-US8-10`, `IT-US8-11`) ไม่ hardcode ข้อความฝั่งหน้าเว็บ |
| 5 | **ข้อมูลหลักสูตรและวิชาโทจริง** | ปรับชื่อหลักสูตรและวิชาโทให้ตรงกับข้อมูลจริงในเล่มหลักสูตร CS มธ. (ฉบับปรับปรุง พ.ศ. 2566):<br>• วิชาโท 4 แขนง: 1. วิทยาการข้อมูล, 2. ปัญญาประดิษฐ์, 3. การออกแบบและพัฒนาผลิตภัณฑ์ดิจิทัล, 4. เดฟออปส์<br>• แผนชั้นปี 3–4: แผน "เลือกทำหัวข้อพิเศษ" (`SPECIAL_PROJECT`) และแผน "เลือกสหกิจ" (`CO_OP`)<br>• ข้อมูลเวลาชนจริง: ปี 3 ภาค 2 วิชาโทวิทยาการข้อมูล (`CS246`) เวลาชนกับวิชาแผนหลัก (`CS314`) |
| 6 | **กรณีผู้ใช้มีหลายหลักสูตร (`curricula.length > 1`)** | ออกแบบเคส `IT-US8-34` รองรับกรณี `curricula.length > 1` โดย UI จะแสดงตัวเลือก "หลักสูตร" ให้ผู้ใช้เลือกก่อน และเมื่อเลือกแล้วจะกรองแผนการเรียนและวิชาโทเฉพาะของหลักสูตรนั้น และเรียก preview อัตโนมัติ |
